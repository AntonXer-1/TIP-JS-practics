## 4. Модель данных и функции

Задача содержит положительный безопасный целый `id`, очищенный `title` длиной 1–100 по `.length`, логический `completed` и приоритет `low`, `medium` или `high`. При создании `completed` равен `false`, приоритет по умолчанию — `medium`. Идентификатор остаётся тем же после удаления соседних записей, поэтому поиск сравнивает свойство `id` и аргумент через `===`.

[src/data.js](src/data.js) содержит исходные наборы. [src/task-service.js](src/task-service.js) выполняет операции с переданными массивами. [src/main.js](src/main.js) запускает два сценария и форматирует вывод.

| Функция | Результат |
|---|---|
| `createTask` | `{ ok: true, task }` или `{ ok: false, error }` при некорректном поле. |
| `findTaskById` | Найденная задача или `undefined`. |
| `getPendingTasks` | Новый массив невыполненных задач. |
| `getTaskTitles` | Новый массив названий в исходном порядке. |
| `getTaskStats` | `{ total, completed, pending, progress }`. Для пустого массива все поля равны нулю. |
| `addTask` | При успехе новый массив с задачей в конце. Некорректное поле или повторный `id` дают отказ. |
| `setTaskCompleted` | При успехе новый массив с изменённым статусом задачи. Некорректный аргумент или отсутствующий `id` дают отказ. |
| `renameTask` | При успехе новый массив с очищенным названием задачи. Некорректный аргумент или отсутствующий `id` дают отказ. |
| `removeTask` | При успехе новый массив без указанной задачи. Некорректный или отсутствующий `id` дают отказ. |

Четыре операции со списком возвращают `{ ok: true, tasks }` при успехе и `{ ok: false, error }` при отказе. При смене статуса и названия создаются новый массив и новый объект выбранной задачи. Остальные записи сохраняются. `progress` возвращается числом без округления, чтобы его можно было использовать в расчётах. `toFixed(1)` применяется в `main.js` при выводе.
